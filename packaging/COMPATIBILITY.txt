MoneyTracker 1.0.8+9 — data compatibility

DATA FORMAT CHANGES: v3 -> v4. Older v1/v2/v3 data is supported and upgraded
with a verified complete backup before registration. Imports preserve the source.
SQLITE UNCHANGED: undo schema v1; existing tables, history rows and blobs remain.
BANK KEYS UNCHANGED: MTK1 / AES-GCM and the original OS credential-store key.

v4 adds optional rule userId and per-user useSharedRules/usePersonalRules flags.
Existing rules remain shared without rewriting rules, transactions, categories,
tags or credentials. Shared and personal rules combine with OR for each label.
Personal category rules win conflicts; manual category overrides win above both.
Matching tags from either enabled pool accumulate. Each user's pools can be
independently enabled or disabled. Unassigned accounts use shared rules.

For a duplicate merged across accounts, the canonical account's user owns the
rule evaluation. If unassigned, a unique linked user is used; otherwise only
shared rules apply. Switching dashboard views never changes classification.
Deleting a user keeps their personal rules inactive; Undo can restore them.

The upgrade receipt and backup location are shown in Overview and retained in
Preferences -> Data and updates. Financial file bytes and compressed undo/redo
history are preserved by the upgrade. The format marker stays outside Undo.

DO NOT OPEN v4 DATA IN OLDER APPS. Versions 1.0.6/1.0.7 refuse v4; earlier
versions lack guards and can misapply personal rules to everyone. To downgrade,
close all copies, preserve the current folder, and restore the complete backup's
data/ contents to the original data location. Keep the same OS user/keyring and
original PEM. Do not mix individual JSON files with an unrelated undo database.

Unknown newer data/undo versions are refused before writing. Importing native
credentials requires the original unlocked OS keyring; the source is preserved.

Full format and recovery documentation:
https://github.com/brunoloff/MoneyTracker/blob/main/docs/DATA_FORMATS.md
